# Antigravity Project Instructions: Oluwaseyi Portfolio

## Project Goal
Build a polished, responsive personal portfolio website for Oluwaseyi, presenting two equally important service areas:
1. AI Automation
2. Website Design & Development

The website should demonstrate strong design judgment and technical competence. Treat it as a premium portfolio, not a generic template.

## Personal Brand and Messaging
- Name: Oluwaseyi
- Primary positioning: AI Automation, Website Design & Development
- Core introduction: "I build AI-powered business systems, automate workflows, and design and develop modern websites and web applications."
- Supporting message: "I combine automation tools, AI agents, and modern web technologies to help businesses streamline operations, improve customer experiences, and bring digital ideas to life."
- Keep the tone clear, confident, human, professional, and specific. Avoid exaggerated claims, empty buzzwords, and invented achievements.

## Public-Facing Messaging and Privacy of Development Workflow
- Never mention or imply in the public-facing website that the portfolio or any website was "vibe-coded," AI-coded, generated by AI, or built with AI-assisted development.
- Do not disclose the use of coding agents or website-building tools. Do not include tool names such as Antigravity, Lovable, Claude, or Gemini in public-facing website copy, project cards, case studies, metadata, social previews, footer text, or UI labels for the purpose of describing how a website was built.
- Describe the services, skills, design decisions, functionality, and verified outcomes instead of the private development method.
- This restriction does not prevent describing AI automation, AI agents, or AI-powered solutions as services offered to clients. Those are part of the professional offering and are distinct from disclosing how a website was created.
- Keep internal project instructions internal. Never render this instruction file or its private implementation notes as website content.

## Design Direction
Use the supplied visual references as inspiration for a premium editorial portfolio. Do not copy another agency's wording or brand identity.

### Strict black-and-white palette
- Main background: #FFFFFF
- Main text: #000000
- Secondary text: #333333 or #555555
- Borders and dividers: #E5E5E5
- Primary button: black background (#000000) with white text (#FFFFFF)
- Button hover: white background with black text and a clear black border
- Do not use blue, purple, colored gradients, or colorful UI accents.
- Project screenshots and website previews may retain their original colors; the portfolio interface around them should remain monochrome.

### Visual language
- Premium, minimal, editorial, high contrast, with generous whitespace.
- Large, bold, confident headlines and legible supporting copy.
- Asymmetric layouts, oversized project previews, carefully controlled overlap, and thick black dividers where appropriate.
- Use angled or overlapping project mockups sparingly and only when they improve the composition.
- Prefer a deliberate, art-directed layout over a generic grid of identical cards.
- Use restrained transitions and hover states. Avoid distracting animations and effects that harm readability.
- Avoid unnecessary gradients, glassmorphism, random decorative icons, excessive rounded cards, or template-like sections.

## Engineering Standards
- Inspect the existing project structure before changing files.
- Reuse established patterns and components where reasonable.
- Build reusable components and keep content separate from presentation when practical.
- Use semantic HTML and accessible labels, focus states, keyboard navigation, and sufficient contrast.
- Make every section responsive, starting with small screens as well as desktop.
- Ensure navigation, buttons, project links, and calls to action work. Never create fake or dead interactions.
- Use real supplied project screenshots and working URLs when available. Never invent project URLs, GitHub repositories, testimonials, customers, metrics, or awards.
- If assets or project links are missing, use clearly named placeholders and document what the owner needs to supply. Do not silently fabricate evidence.
- Optimize images and avoid unnecessary animation or oversized assets.
- Respect reduced-motion preferences.
- Validate forms and handle errors if a contact form is implemented.
- Never put secrets, API keys, private customer data, or credentials in source code.
- Do not add backend services, analytics, payment systems, or external integrations unless required and configured appropriately.
- Check the app by running available lint, type-check, test, and build scripts. Report any checks that cannot be run.
- Do not claim the website is complete or verified if it has not been run and checked.

## Working Process for Antigravity
1. Inspect the repository and available assets before implementing.
2. Summarize the proposed structure and identify any important missing content.
3. Implement the agreed design using the existing project conventions.
4. Verify responsive behavior and interactive elements.
5. Run available checks and fix errors where feasible.
6. Summarize files changed, features implemented, checks run, and any remaining placeholders.

When details are missing, make a conservative implementation choice and clearly mark anything requiring owner confirmation. Do not repeatedly ask for details that are not necessary to make progress.
